TL;DR

Azri turns any GitHub repo or PR into a self-contained explanation page in under a minute.

It runs a six-stage LLM pipeline that triages the input, plans the document outline, fills each section in parallel, and renders a single CDN-only HTML file ready to share with reviewers, teammates, and stakeholders.

Architecture Decision

CDN-first rendering vs. self-contained bundles

Decision

Ship the renderer as a thin HTML shell that pulls Tailwind, Mermaid, and Lucide from public CDNs.

Why

CDN delivery keeps the generated file under 200 KB while preserving full Tailwind utility coverage. Cache hit-rates on jsDelivr push median load time below 600 ms even on fresh devices.

Alternatives considered

  • ×
    Inline every dependency as base64 into the HTML — Bundle size balloons past 2 MB and breaks GitHub Pages caching.
  • ×
    Run a build step that produces a hashed Tailwind bundle per theme — Requires a Node build pipeline at render time and defeats the "single binary" promise.

Gain

Tiny HTML output, instant updates when Tailwind ships fixes, no local build dependency.

Cost

Requires network access to render the page; CSP must permit jsdelivr and simpleicons CDNs.

Data flow through the pipeline

flowchart LR
  Input[Repo or PR URL] --> S0[Triage]
  S0 --> S1[Summarize]
  S1 --> S2[Plan]
  S2 --> S3[Produce]
  S3 --> S4[Render]
  S4 --> S5[Validate]
  S5 --> Out[Self-contained HTML]
  1. 1 The CLI clones the repo or pulls the PR diff into memory.
  2. 2 Triage emits a structured summary with languages, manifest contents, and tree shape.
  3. 3 The planner asks the LLM to pick an ordered list of sections from the registry.
  4. 4 The producer dispatches each section prompt in parallel, validating responses against Zod.
  5. 5 The renderer assembles every section into the page shell and writes it to disk.

Notes: Each stage emits structured logs; failures retry once with the prior error in context before being skipped.

Tailwind Play CDN requires inline styles

The Tailwind v4 browser build injects runtime <style> tags, so the page CSP must allow style-src 'unsafe-inline'.

Suggestion: Document the relaxed CSP and offer a strict mode that swaps to a pre-built bundle.

Rollback plan

Simple
  1. 1

    Revert the gallery + renderer changes.

    git revert <commit-sha>
  2. 2

    Confirm the working tree is clean post-revert.

    bun run check && bun test
Warnings
  • If the revert lands after a release tag, also yank the npm version.

Data migration

Reversible

No persisted data is touched; the change is purely renderer-side.
