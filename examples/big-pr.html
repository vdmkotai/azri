test: node:test compatibility shim on top of bun:test

Maps node:test's test(), describe(), and the before/after lifecycle hooks onto Bun's existing test graph. ~1,400 lines added across the runner, the JS bindings, and the C++ TestRunner module. 47 new tests in test/cli/test/. The shim is opt-in via --test-runner=node-compat; the default runner is unchanged.

Overview

Bun ships its own test runner (bun:test). Node 18+ ships node:test. The two have overlapping APIs and incompatible expectations: node:test reports via TAP, treats every callback as a subtest scope, and runs hooks per-test by default. bun:test reports via a custom format, uses Jest-style describe blocks, and runs hooks per-block.

This change adds a compatibility shim so existing Node test suites run under Bun without a rewrite. The shim is gated behind --test-runner=node-compat (a new flag). The default bun test behavior is unchanged.

Numbers from the included compatibility matrix (test/cli/test/node-compat.matrix.test.ts):

  • node:test example suites that pass without changes: 18 of 24 from the official Node test docs
  • Failing suites and why:
    • 3 rely on t.diagnostic() (not yet implemented — see follow-ups)
    • 2 rely on --test-name-pattern regex syntax that differs from Bun's glob
    • 1 mixes before and beforeEach in a way the shim normalizes to beforeEach, changing test order

The shim does not change process.argv, the exit code semantics, or the TAP output format that Node consumers depend on.

Compatibility surface

The shim covers four entry points and four lifecycle hooks. Everything else falls through to the existing bun:test graph or throws a NotImplementedError with a CHANGELOG link.

Supported entry points (mapped to bun:test):

  • test(name, fn) — registered as a leaf test in the current describe scope
  • test(name, opts, fn) — opts.skip, opts.only, opts.timeout, opts.concurrency are honored; unknown keys log a warning
  • describe(name, fn) — pushes a new scope; same as bun:test
  • it(name, fn) — alias for test(), same semantics

Supported lifecycle hooks:

  • before(fn) → maps to beforeAll(fn)
  • after(fn) → maps to afterAll(fn)
  • beforeEach(fn) → unchanged
  • afterEach(fn) → unchanged

The before/after → beforeAll/afterAll mapping is the one place the semantics shift. In node:test, before runs once before the first subtest under its scope. In bun:test, beforeAll runs once before the entire describe block. For 95% of suites these are observationally identical. For the other 5% — suites that mix before and beforeEach and care about ordering — the shim emits a deprecation notice the first time it sees the pattern, with a pointer to the workaround.

Risks we're watching

Six risks were flagged. Two are blockers if uncovered in production; the rest are watch-list items with documented workarounds.

api-contract

The shim claims compatibility with node:test but covers only 75% (18/24) of the official examples. Suites using `t.diagnostic()`, regex `--test-name-pattern`, or mixed `before`/`beforeEach` will either fail outright or behave differently. The CHANGELOG entry must list the gaps explicitly; the docs PR is queued as follow-up #2.

test-coverage

Hook normalization (before → beforeAll) silently changes test ordering for suites that mix before and beforeEach. A deprecation notice is emitted on first encounter, but suites that suppress warnings will see incorrect behavior with no signal. Recommend escalating the notice to an error in a future minor.

performance

The transpiler injection path adds ~180μs to module load for files importing node:test (measured on M2 Pro with --test-runner=node-compat). For typical suites of <100 test files this is invisible; for suites with thousands of small test files the overhead is observable. The follow-up bundling pass would cut this to ~30μs.

dependency-change

No third-party dependencies added. The shim is implemented in Zig and C++ against Bun's existing runtime. The TAP reporter reuses the existing `tap.zig` module, which is unchanged.

secrets-exposure

The telemetry counter (follow-up #4) writes to `~/.bun/telemetry/test-runner.count` and never leaves the machine. The local-only design was reviewed against the Bun privacy policy; see the linked design note in the PR description for the threat model.

auth

The shim has no auth surface, but the new `--test-runner` flag interacts with the existing `--preload` script path. A preload script can swap the active runner at runtime via `process.argv` manipulation; downstream CI configs that pin `--test-runner=default` for security reasons should add an assertion in their preload script.

The new test() shim

src/bun.js/test/jest.zig — the shim lives in a new node_compat module. The existing bun:test graph is untouched.

+const node_compat = struct {
+    fn registerTest(
+        globalObject: *JSGlobalObject,
+        callframe: *CallFrame,
+    ) callconv(.C) JSValue {
+        const args = callframe.arguments(3);
+        const name = args.ptr[0];
+        const opts_or_fn = args.ptr[1];
+        const maybe_fn = args.ptr[2];
+
+        // Two-arg form: test(name, fn)
+        if (maybe_fn.isUndefined()) {
+            return jest.describe.test_(globalObject, name, opts_or_fn, .{});
+        }
+        // Three-arg form: test(name, opts, fn)
+        const opts = parseNodeTestOpts(globalObject, opts_or_fn);
+        return jest.describe.test_(globalObject, name, maybe_fn, opts);
+    }
+};

The shim does not duplicate the test scheduling logic. It parses node:test's option shape ({ skip, only, timeout, concurrency }), converts it to bun:test's internal TestOpts struct, and forwards to the same jest.describe.test_ function the existing code uses.

src/bun.js/api/JSTranspiler.cpp — the transpiler injects the shim's globals into modules that import node:test.

+    if (specifier == "node:test"_s) {
+        return makeNodeTestRecord(globalObject);
+    }

The makeNodeTestRecord helper returns a synthetic module exporting test, describe, it, and the four hooks. No bytecode is generated — the entries are pre-bound JSFunction values that route into the Zig shim.

Test runner refactors

The CLI gains a --test-runner flag with two values: default (current behavior) and node-compat (the new shim). The default is unchanged; suites built for bun:test continue to work.

 const TestCommand = struct {
     pub fn exec(ctx: Command.Context) !void {
+        const runner = ctx.runtime_options.test_runner;
+        switch (runner) {
+            .default => try execDefault(ctx),
+            .node_compat => try execNodeCompat(ctx),
+        }
-        // ... existing default-runner code ...
     }
 };

The execNodeCompat path differs from execDefault in three places:

  1. Reporter selection: --test-reporter=tap is forced; other reporters print a warning and exit non-zero.
  2. Hook normalization: a pre-pass on the registered test graph rewrites before → beforeAll and after → afterAll.
  3. Test name pattern: the --test-name-pattern flag is interpreted as a JavaScript regex instead of a glob, matching node:test.

Test coverage

47 new tests across three files. The matrix file is the headline check; it runs each of the 24 official node:test example suites under bun test --test-runner=node-compat and snapshots the TAP output.

Breakdown:

  • node-compat.matrix.test.ts (24 tests): one per example suite from the Node test docs. 18 pass, 6 are marked .skip with an inline reason and a tracking issue link.
  • node-compat.hooks.test.ts (15 tests): exhaustive coverage of the before/beforeEach/after/afterEach matrix. Includes the deprecation-notice path for mixed before + beforeEach.
  • node-compat.tap.test.ts (8 tests): TAP output format conformance against the official spec. Validates ok/not-ok lines, diagnostic comments, and the bail-out behavior on the first failure.

The default-runner test suite is untouched and continues to pass. The CI matrix gains a third axis for --test-runner values, taking the total CI test count from 12,400 to 14,200.

Module impact

Three files own the new code. Nothing else moves.

  • src/bun.js/test/jest.zig (+820 lines): the node_compat struct, the option-shape parser, the hook-normalization pre-pass.
  • src/cli/test_command.zig (+340 lines): the --test-runner flag, the execNodeCompat path, the TAP reporter routing.
  • src/bun.js/api/JSTranspiler.cpp (+240 lines): the node:test module synthesis and the pre-bound JSFunction values.

No public C++ headers change. The Zig public API gains one new exported function (Jest.shimNodeTest) which the transpiler calls. The function is pub but not documented; downstream code embedding Bun's runtime should not call it directly.

Follow-ups

Four items are queued behind this PR:

  1. t.diagnostic() support. Three of the six failing suites need it. The implementation is small (~80 lines in the TAP reporter); separated to keep this PR focused on the shim itself.
  2. --test-name-pattern glob/regex unification. The current implementation switches behavior based on --test-runner. A planned follow-up exposes both syntaxes via a --test-name-pattern-syntax flag, defaulting per-runner.
  3. Documentation. The docs/cli/test.md page gains a 'Compatibility with node:test' section. The 18 passing suites are listed with copy-paste invocations; the 6 failing suites are listed with their tracking issues.
  4. Telemetry. A counter increments on each invocation of --test-runner=node-compat so the team can track adoption. The counter is local-only and never sent off the machine; opt-out via BUN_DISABLE_TELEMETRY=1 as today.
