router: thread RequestContext through handlers instead of FiberRef

Routes now take a typed RequestContext as their first argument. Drops two hidden allocations per request and removes three deprecated exports from the package surface. Local benchmark shows -28% median latency on a four-layer middleware stack.

View on GitHub →
Run example-pr-explainer · 2026-05-22T10:18:00Z

Overview

HttpRouter held per-request state in a FiberRef<Request | null>. Every middleware boundary cloned the fiber graph to scope that state, which cost roughly 6μs and one allocation per layer on the included router benchmark.

The new shape: handlers take a RequestContext argument. The router builds it once at the dispatch boundary, passes it down, and the FiberRef goes away. Three exports tied to it (CurrentRequest, withRequest, getRequestRef) are removed from effect/unstable/http.

Existing routes keep working without changes. A small wrapper at packages/http/src/HttpRouter.ts:142-158 adapts handlers that match the old (req) => Effect<Response> shape; the wrapper carries a @deprecated JSDoc tag and will be removed in 4.0.0-beta.78.

Numbers from packages/http/bench/router.bench.ts (Bun 1.3.14, M2 Pro, four-layer middleware stack, 10k iterations):

  • Median latency per request: 5.8ms → 4.1ms
  • p99 latency: 9.2ms → 6.0ms
  • Allocations per request (heap-snapshot diff): 14 → 11

How the new context flows

The router builds a RequestContext once when a request arrives. The context is immutable, shape-checked, and carries only what handlers are allowed to read: the raw Request, the parsed URL, the path params, and the abort signal tied to the connection.

Middleware composes by passing the same context down the chain. There is no escape hatch back to fiber-local state and no setter on the request. Routes that need to write headers do so on the returned Response, which is the only place mutation lives.

This is intentionally narrow. The old FiberRef<Request | null> had a null arm because nothing stopped code from running outside a request. The new shape makes that statically impossible — handlers cannot be invoked without a context.

Risks we're watching

Four risks were flagged during review. None are blocking, but the api-contract item below is the one to read carefully if you maintain a downstream package.

api-contract

Three public exports (`CurrentRequest`, `withRequest`, `getRequestRef`) are removed from `effect/unstable/http`. Downstream code importing them will fail to compile against this version. Eleven published dependents flagged via `npms.io`; all are listed in the CHANGELOG with the one-line replacement.

performance

Microbenchmark shows -28% median request latency on the included four-layer middleware stack (5.8ms → 4.1ms). No production telemetry yet; the win is from removing FiberRef clones, not from algorithmic changes, so the effect should be roughly linear in middleware depth.

test-coverage

Eleven new tests cover nested middleware, header propagation, abort signals, path params, and 404 handling. One test for fiber-scoped cancellation was removed; the scenario is now exercised by the abort-signal test at line 130, but a corner case where the fiber is cancelled mid-middleware is no longer directly tested.

dependency-change

No new dependencies. The `@effect/core` peer range is unchanged at `>=3.0.0`. The `effect/unstable/http` package version bumps to `0.4.0` to signal the breaking surface change.

packages/http/src/RequestContext.ts — new module, 24 lines, no implementation logic.

export interface RequestContext {
  readonly req: Request
  readonly url: URL
  readonly params: ReadonlyMap<string, string>
  readonly signal: AbortSignal
}

export const make = (req: Request, params: ReadonlyMap<string, string>): RequestContext => ({
  req,
  url: new URL(req.url),
  params,
  signal: req.signal,
})

packages/http/src/index.ts — three exports removed, one added.

-export { CurrentRequest, withRequest, getRequestRef } from "./HttpRouter.js"
+export type { RequestContext } from "./RequestContext.js"
+export { make as makeContext } from "./RequestContext.js"

The removed names were marked @deprecated two minors ago. CHANGELOG entry at packages/http/CHANGELOG.md:14-22 calls this out under BREAKING CHANGES.

Module impact

The change is scoped to packages/http. Both platform adapters (platform-node, platform-bun) consume the router through the public route definition API, which is unchanged. No code in those packages had to move.

Downstream packages that imported the deprecated exports (CurrentRequest, withRequest, getRequestRef) need to migrate. An npm search via npms.io found 11 published dependents touching those names. All 11 are listed in the CHANGELOG with the one-line replacement. The migration is mechanical: replace yield* CurrentRequest with the ctx argument.

Internal call sites inside the monorepo: zero. Earlier passes had already moved @effect/experimental/sse and @effect/rpc-http off the FiberRef path.

Test coverage

Eleven tests added in packages/http/test/HttpRouter.test.ts:88-201, covering:

  • Nested middleware with three layers passing the same context (lines 88-110)
  • Header propagation through ctx.req.headers (lines 112-128)
  • Abort signal plumbing from the client through to a slow handler (lines 130-152)
  • Path param parsing for routes with two and three segments (lines 154-178)
  • 404 handling when no route matches and no fallback is configured (lines 180-201)

The seven tests that previously read from the FiberRef were rewritten in place. One test for fiber-scoped cancellation was deleted; the same scenario is now covered by the abort-signal test at line 130, which is closer to how production code observes cancellation.

After this lands

Three follow-ups are queued behind this PR:

  1. Remove the deprecated wrapper at packages/http/src/HttpRouter.ts:142-158 in 4.0.0-beta.78. The wrapper exists only so the major bump can be a single, isolated PR.
  2. Constructor-time route compilation. With the FiberRef gone, the router's hot path is dominated by route.match calls. A planned follow-up compiles routes into a single regex on make(), which the benchmark suggests would cut another 1.2ms off median latency.
  3. Cancellation telemetry. The abort signal now flows through ctx.signal. The observability package will add a span event when a handler exits via abort, which is currently invisible.
